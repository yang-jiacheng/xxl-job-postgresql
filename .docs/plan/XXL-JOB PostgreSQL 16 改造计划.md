## 1. 目标

将当前定制的 XXL-JOB Admin 2.4.1 从 MySQL-only 改为 PostgreSQL-only：

- PostgreSQL 16.15。
- 数据库 `test_db`，业务模式 `app`。
- 仅支持全新初始化。
- 不提供 MySQL 存量数据迁移。
- 不保留 MySQL/PostgreSQL 双方言。
- 保持 Java 8、Spring Boot 2.7.18、原生 MyBatis 和当前 v2.4.1 业务行为。
- 不引入 MyBatis-Plus，不借机升级到 XXL-JOB 3.1.0。

本计划只覆盖数据库适配。上游 2.5.0/3.x 的 Registry 并发优化、日志索引、AI 示例、调度修复、认证、安全和前端变化不纳入本轮。

## 4. 详细方案

### 4.1 PostgreSQL 初始化脚本

文件：`.docs/deploy/tables_xxl_job.sql`。

前置条件：

- `test_db` 和 `app` 已存在。
- 执行用户对 `app` 有 USAGE 和 CREATE。
- `app` 不存在同名 `xxl_job_*` 对象。
- 不删除或修改现有 `app.test_tb`。

DDL 方案：

- 使用单事务，并在事务内 `SET search_path TO app`。
- 创建 v2.4.1 原有的 8 张表，不增加表、不减少列。
- 7 个自增主键使用 `GENERATED BY DEFAULT AS IDENTITY`。
- 11 个时间列使用 `timestamp` 简写；PostgreSQL 将其解析为 `timestamp without time zone`，不引入时区转换。
- 类型映射：

  - `int` → `integer`
  - `bigint` → `bigint`
  - `tinyint` → `smallint`
  - `datetime` → `timestamp`
  - `mediumtext` → `text`
  - `varchar(n)`、`text` 保持等价类型

- MySQL 行内 `COMMENT` 改为 `COMMENT ON TABLE/COLUMN`。
- 普通索引保持 3 个：

  - 日志 `trigger_time`
  - 日志 `handle_code`
  - Registry `(registry_group, registry_key, registry_value)`

- 唯一索引保持 2 个：

  - 日报 `trigger_day`
  - 用户 `username`

- Registry 三元组不改为唯一索引；这是 v2.4.1 与 v3.1.0 的明确版本边界。
- 保留 1 个执行器组、1 个任务、1 个管理员用户和 `schedule_lock`。
- 固定 ID 种子写入后同步 `xxl_job_group`、`xxl_job_info`、`xxl_job_user` 的 identity sequence。
- 不增加外键、检查约束、级联规则或 v3.1.0 的额外日志索引。
- 遵循 `.docs/sql-style.md`，使用 UTF-8 无 BOM 和 ASCII 标点。

### 4.2 POM

文件：`pom.xml`。

- MySQL Connector/J 的版本属性、dependency management 和实际 dependency 已删除。
- pgJDBC 42.7.13 已加入 dependency management 和实际 dependencies，scope 为 compile；pgJDBC 42.7.x 的最低 Java 版本为 Java 8。
- 保持 Java 8、Spring Boot 2.7.18、MyBatis starter 2.3.2。
- 保持 `com.alibaba:druid-spring-boot-starter:1.1.24`，不切换到 Boot 3 starter。
- 用户已显式加入 Guava 33.5.0-jre compile 依赖；本轮保留该用户决定，不把它误写成 Druid 1.1.24 的已验证必需依赖。
- 不运行 Maven 编译；只做 XML 解析和依赖声明一致性检查。

### 4.3 数据源与 schema

文件：`src/main/resources/application.properties`。

- `spring.datasource.druid.db-type=postgresql`。
- `spring.datasource.driver-class-name=org.postgresql.Driver`。
- JDBC URL 使用 `jdbc:postgresql://...` 并确保最终有效 URL 带 `currentSchema=app`。
- `validation-query=SELECT 1`。
- 以 `currentSchema=app` 为主策略，保持 connection-init-sqls 注释，避免文档描述与实际配置不一致。
- 不在文档、提交说明或检索请求中传播配置里的密码、Token 等敏感默认值。
- 是否移除本地敏感默认值由用户决定；数据库方言改造不得擅自改变认证口径。

### 4.4 Group / Info / User Mapper

- 删除 SQL 标识符反引号。
- 分页改为 `LIMIT #{pagesize} OFFSET #{offset}`。
- 为保持 MySQL 常见大小写不敏感搜索体验，模糊查询改为 `ILIKE '%' || 参数 || '%'`。
- 删除 `LAST_INSERT_ID` 等失效注释。
- 3 个 generated-key insert 增加 `keyColumn="id"`。
- 不移植 v3.1.0 的 `scheduleUpdate` 条件更新逻辑；那是上游调度行为升级，不是 PostgreSQL 方言要求。

### 4.5 Log Mapper

- 分页改为 PostgreSQL `LIMIT/OFFSET`。
- 删除反引号，`!(...)` 改为标准 `NOT (...)`。
- 清理日志 ID 子查询中的 `LIMIT 0, n` 改为 `LIMIT n`，并移除 MySQL 为绕过修改表限制而使用的多余嵌套。
- `findLogReport` 的 3 个 camelCase Map 键使用双引号别名：

  - `"triggerDayCount"`
  - `"triggerDayCountRunning"`
  - `"triggerDayCountSuc"`

- generated-key insert 增加 `keyColumn="id"`。
- 比较符可统一使用 `&lt;` / `&gt;` XML 实体，确保 XML 可解析。

### 4.6 LogGlue / LogReport Mapper

- 删除反引号和 `LAST_INSERT_ID` 注释。
- LogGlue 的保留数量清理改为 PostgreSQL `LIMIT` 写法并简化嵌套。
- 两个 generated-key insert 增加 `keyColumn="id"`。

### 4.7 Registry Mapper

当前 v2.4.1 方案：

- `findDead`：
  `t.update_time < CAST(#{nowTime} AS timestamp) - #{timeout} * INTERVAL '1 second'`
- `findAll`：
  `t.update_time > CAST(#{nowTime} AS timestamp) - #{timeout} * INTERVAL '1 second'`
- 显式 `CAST` 用于固定 pgJDBC 参数类型，避免形成 `timestamp < interval` 的非法比较。
- 删除 `registryUpdate` 和 `registrySave` 中的反引号。
- 保留 Mapper ID、DAO 方法和 `JobRegistryHelper` 的 update-then-insert 流程。
- 不使用 `ON CONFLICT`，因为 v2.4.1 的 Registry 三元组不是唯一键，Java 也没有 `registrySaveOrUpdate` 契约。

若用户将来决定吸收 v2.5+/3.1.0 的原子注册方案，必须把唯一索引、DAO、Helper、Mapper 和并发验证作为一个独立变更整体实施。

### 4.8 Docker

文件：`.docs/deploy/xxljob-docker/README.md`。

- 示例镜像/构建版本与当前 2.4.1 分支一致，不继续写 3.1.0。
- MySQL URL 改为 PostgreSQL URL。
- `DB_URL` 示例包含 `currentSchema=app`。
- 说明 `app` 需预先存在、执行用户需有权限、初始化脚本由用户执行。
- 不在示例中填写真实用户名、密码或 Token。

## 5. 验证计划

### 5.1 静态验证

按项目规则不运行 Maven 编译。改用：

- 解析 `pom.xml` 和 7 个 Mapper XML。
- 检查 properties 无重复键。
- 检查 6 个 generated-key insert 均有 `keyColumn="id"`。
- 检查代码引用表集合与 DDL 的 8 表集合一致。
- 检查 DDL 含 8 个主键、7 个 identity、3 个普通索引、2 个唯一索引。
- 检查 DDL 固定 ID 种子和 3 个 sequence 同步逻辑。
- 在 POM、properties、Mapper、DDL、Docker 范围扫描：

  - MySQL 驱动和 JDBC URL
  - 反引号
  - `AUTO_INCREMENT`
  - `ENGINE=InnoDB`
  - `DATE_ADD`
  - `ON DUPLICATE KEY UPDATE`
  - `LAST_INSERT_ID`
  - `DATE_FORMAT`
  - MySQL 逗号分页

历史会话文档和“禁止项”说明可出现这些关键词，不作为有效残留。

静态验证结果（2026-09-05）：POM 与 7 个 Mapper XML 均可解析；7 组 DAO/Mapper statement 无差异；6/6 generated-key insert 含 `keyColumn="id"`；properties 无重复有效键；代码与 DDL 均引用同一组 8 张表；DDL 为 8 主键、7 identity、3 普通索引、2 唯一索引、3 次 sequence 同步和 11 个 `timestamp` 列；与改造前 v2.4.1 DDL 对比，8 表的列名、顺序和类型映射无差异；相关文件均为 UTF-8 无 BOM。按项目规则未运行 Maven。

### 5.2 数据库结构验证

DDL 已由用户执行，Agent 已按以下项目完成只读核验：

2026-09-05 最终结果：`app` 中 8 张表和 69 列与脚本一致，`public` 没有误建同名表；8 主键、7 identity、5 个二级索引、4 类种子及 group/info/user 的 sequence 状态正确，`app.test_tb` 仍在。数据库元数据将脚本中的 `timestamp` 简写规范化显示为 `timestamp without time zone`，两者语义相同。

- `app` 中 8 张 XXL-JOB 表存在，且 `public` 没有误建同名表。
- 8 个主键、7 个 identity、3 个普通索引、2 个唯一索引正确。
- 列类型、可空性和默认值与 DDL 一致。
- Registry 三元组索引为普通索引。
- 4 类种子数据存在。
- group/info/user 的下一个 identity 值不会与固定 ID 冲突。
- `app.test_tb` 仍存在且未被修改。

### 5.3 运行验证

1. 数据源建立连接并确认 schema。
2. 调度锁获取。
