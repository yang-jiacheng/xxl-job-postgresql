### 4.4 Registry 时间参数推断错误

- 用户提供的后续日志在 `JobRegistryHelper` 的 `findDead` 查询中报错：`operator does not exist: timestamp without time zone < interval`。
- 故障 SQL 为 `t.update_time < ? - ? * INTERVAL '1 second'`。DAO 传入的 `nowTime` 是 `java.util.Date`，MyBatis 会调用 `setTimestamp`；pgJDBC 42.7.13 对普通 `Timestamp` 使用未指定类型 OID，PostgreSQL 在解析内部 `未知类型 - interval` 时选择了 `interval - interval`，导致外层成为 `timestamp < interval`。
- `findAll` 使用相同的右侧表达式，也存在同一风险，虽然本次日志首先由 `findDead` 触发。
- 当前代码已将两处右侧时间参数改为 `CAST(#{nowTime} AS timestamp) - #{timeout} * INTERVAL '1 second'`。`timestamp` 在 PostgreSQL 中表示 `timestamp without time zone`，无需重复写出 `without time zone`。
- 本轮同时全量检查了其他 Mapper：没有其他绑定时间参数参与 interval 运算的 SQL；10 处比较符 CDATA 已统一改为 XML 实体。
- 当前只完成代码静态验证，修复后的注册监控运行结果等待用户自行重启确认；Agent 未执行 SQL 或启动应用。
- 日志实际加载的是 `target/classes/mybatis-mapper/XxlJobRegistryMapper.xml`；该构建输出目前仍是修改前的旧副本。Agent 按项目规则未执行 Maven 编译，也未手工修改 `target`，用户重启前需让 IDE 或构建工具重新复制资源。
